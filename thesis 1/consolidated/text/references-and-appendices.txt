                                       APPENDIX B

                         NASA Task Load Index (NASA-TLX)
        Administered immediately after each condition, referring to the set of tasks

just completed. Six subscales are rated on a twenty-one-point scale presented as a line

instrument [14] is omitted, and the composite workload score is the arithmetic mean of

Perfect to Failure), run from low to high workload, so no subscale is reverse-scored.

                                       APPENDIX C

                            Custom Cross-Platform Task Suite
           The suite comprises sixteen tasks in two parts. Twelve core tasks span the

four categories defined in Section 1.5 at three difficulty levels, and constitute the
primary comparison.       Four boundary tasks deliberately fall outside what a shell-

mediated interface can express; they are administered and scored but reported
separately from the primary comparison, because their purpose is to characterize the

capability boundary honestly rather than to contribute to the between-condition
contrast. Omitting them would leave the suite composed only of work the command

line does well, which would make any favourable result difficult to defend.
           Every task exists in two parallel forms, matched on category, difficulty, and

number of required steps, and differing only in target. No participant encounters the
same form twice; form and condition order are crossed as described in Section 2.4. All

prompts are phrased as human goals in plain language, containing no shell syntax, no

──────── p. 115 ────────
                                                                                           115


command names, and no interface-specific vocabulary, so that they are equally
answerable through natural language on SynapseOS and through native tools on the

baseline machine.
        Tasks T7–T9 require identical provisioning on all study machines — the same

designated applications present or absent, and the two test applications (SampleApp,

DemoTool) installed — so that the prompt means the same thing under both conditions
and on all three baseline operating systems; this provisioning is part of the facilitator

checklist in Appendix G. Task T9 is classified irreversible and is included specifically
to exercise the confirmation gate; T11 mutates file content and is included to exercise

the undo journal. Difficulty is assigned by the number of distinct operations required
and the specificity of the target, and is validated during the pilot study described in

Section 2.3.

                                      APPENDIX D
                            Pre-Study Screening Questionnaire

           Completed before enrolment and used to classify each volunteer as a novice or
a power user, and to record the covariates described in Section 1.4. The form records a

participant ID code only; the volunteer’s name appears solely on the consent form
(Appendix F), which is stored separately from all study data. Screening data belonging

to volunteers who are not enrolled is destroyed within seven days of the screening
session.

           Part 1 — Background (self-report)

      1. Are you 18 years of age or older? □ Yes □ No (a “No” response ends the
           screening; the study enrols adults only)

      2. Approximately how many years have you used a computer regularly?
           ____________

      3. Which operating system do you use most? □ Windows □ macOS □ Linux

         Who is running this study. This research is conducted by undergraduate

Computer Science.     It will be carried out only after review and approval by the

         Why we are doing this. Most of what a computer can do is reachable only by

people who know how to write commands for it. We have built a system that lets a
person say what they want in ordinary language — for example, “find the files I

changed last week and put them in one folder” — and carries it out. We want to find
out whether that is genuinely easier to use than the desktop you already use, and

whether it makes more difference for people who have never used a command line.

         What you would do. You would attend one session of about 90 to 120

                                        APPENDIX G
                                 Session Facilitator Checklist

           Followed identically for every participant so that session conduct does not
vary across the sample. Items marked † must be completed before the participant

arrives.
           Before the session †

      1. Restore both machines to the clean baseline image; confirm no data remains
           from the previous participant.

      2. Boot the baseline machine into the operating system matching the participant’s
           screening record (Windows, macOS, or Linux with GNOME).

      3. Provision the task environment identically on both machines: practice file set
           in place, the applications referenced by tasks T7–T9 present or absent as

           specified, and the test applications SampleApp and DemoTool installed.
      4. On the SynapseOS machine, confirm the inference server is running and the

           model is loaded, and run one throwaway task to confirm the system responds.
      5. Confirm screen recording works on both machines and has free storage for the

           full session.
      6. Lay out the printed task prompt sheet for the assigned form, the two

           questionnaire sets, the information sheet, and the consent form.
      7. Record which interface mode SynapseOS is running in for this session, per the

           readiness checkpoint in the System Environment Specifications.

           During the session
      1. Give the information sheet, answer questions, obtain signed consent. File the

           consent form separately from all study materials.
      2. Give the five-minute orientation to the assigned first condition. Use the same

           wording for every participant; do not demonstrate any task from the task set.
      3. Start screen recording. Present tasks one at a time in the randomized order for

           this participant.    Do not prompt, hint, or answer questions about how to
           accomplish a task.

4. Do not ask the participant to think aloud during timed tasks.
