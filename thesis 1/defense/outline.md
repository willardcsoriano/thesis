## Overview

As-built outline for the Thesis 1 proposal defense deck (`SynapseOS_Proposal_Defense.pptx`, generated by `build-deck.js`) — Chapters 1-3 of SynapseOS, defending the research plan and methodology rather than completed results, since the user study has not run yet (IRB still pending per `docs/scope.md` Track B). Content is pulled from the consolidated proposal (`../consolidated/SynapseOS_Proposal_Chapters_1_to_3.html`), the held-out round-7 results (`prototype/pilot/results_round7.txt`), and the project's own decision log (`docs/decisions.md`), not invented for the deck. Two things it deliberately builds in: the round-7 numbers are reported as a frozen held-out result with its own limits named on the slide (single annotator, `open-problems.md` row 27), never oversold as final study findings, and the one open question the adviser has already asked once in writing (the composition/resolution ablation, `open-problems.md` row 38) gets its own slide instead of being left for the panel to raise cold. Both "what it looks like" slides now carry real captured footage of the running prototype (`media/`), not placeholders — recorded by scripting the actual TUI through a real pty and rendering the captured screen state directly to image/GIF, so nothing shown is staged or mocked up. Capturing it surfaced a genuine rendering bug in neat mode, logged as `open-problems.md` row 41 rather than silently worked around.

## Media

`media/what-it-looks-like.gif` and `media/safety-gate.png` are real captures, not mockups or illustrations — produced by driving the actual `prototype/bin/synapse tui scratch` binary through a real pty (Python's `pty` module, scripted keystrokes, realistic character-by-character timing) and rendering the captured terminal state (via `pyte`, a VT100 emulator) straight to PNG/GIF with Pillow and DejaVu Sans Mono, matching the deck's own theme colors. No X11, no screen recording, no sudo — see `docs/testing-environment.md` for the disposable-VM alternative if this ever needs to run somewhere without a local Ollama + the synapse binary built.

The capture script (`capture_demo.py`) lived in the session scratchpad, not this repo — it's a one-off presentation tool, not product code, so it wasn't committed. If the demo needs re-capturing later (a UI change, a different scenario), the approach is: open a real pty, run the binary in it, script input with small per-keystroke delays (an instant full-string write raced the TUI's own input handling — see row 41 below), capture `pyte.Screen` snapshots at the moments worth showing, and render each with Pillow. `demo1_sandbox`/`demo2_sandbox` were throwaway directories with a few sample files for the two scenarios: three varied requests in sequence (a listing, a rename, a count) for slide 6, and a destructive "delete all the log files in this folder" for slide 8, declined after capturing the gate. One phrasing worth knowing about if re-recording: "how many photos are in here?" ran unusually long on the 3B model (45s+, still unfinished) where "count the files in the Photos folder" answered cleanly in well under its wait budget — more direct/explicit wording seems to matter for latency with this model size, not just correctness.

**Found while capturing:** neat mode duplicates the echoed `> <task>` line on multi-step tasks (command + composed answer) — not on single-step conversational ones, and not in plain CLI mode or non-neat TUI mode. Reproduced 3/3 live. Logged as `open-problems.md` row 41 with what's already been ruled out; root cause not yet found. The shipped images are clean — a cosmetic-only dedup in the capture script's renderer (not in product code) drops an immediately-repeated identical line before drawing, so the real bug is visible in the TUI today but not in these slides.

## Rebuilding the deck

```sh
cd "thesis 1/defense"
npm install pptxgenjs react-icons react react-dom sharp   # once; node_modules is not committed
NODE_PATH="$(pwd)/node_modules" node build-deck.js
```

Edit content, numbers, sizing, or theme colors directly in `build-deck.js`, then rerun. See that file's own header comment for the `applyTheme` dependency on the Claude Code `pptx` skill, and its sizing/notes policy comment before changing either. Image paths in `addImage()` calls are resolved relative to the working directory the script is run from — run it from `thesis 1/defense/` as shown above, not from the repo root.
