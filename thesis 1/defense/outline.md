## Overview

As-built outline for the Thesis 1 proposal defense deck (`SynapseOS_Proposal_Defense.pptx`, generated by `build-deck.js`) — Chapters 1-3 of SynapseOS, defending the research plan and methodology rather than completed results, since the user study has not run yet (IRB still pending per `docs/scope.md` Track B). Content is pulled from the consolidated proposal (`../consolidated/SynapseOS_Proposal_Chapters_1_to_3.html`), the held-out round-7 results (`prototype/pilot/results_round7.txt`), and the project's own decision log (`docs/decisions.md`), not invented for the deck. Two things it deliberately builds in: the round-7 numbers are reported as a frozen held-out result with its own limits named on the slide (single annotator, `open-problems.md` row 27), never oversold as final study findings, and the one open question the adviser has already asked once in writing (the composition/resolution ablation, `open-problems.md` row 38) gets its own slide instead of being left for the panel to raise cold. Three "real footage" slides carry captured output of the running prototype (`media/`), recorded against real, locally-browsable demo folders, not mockups or an ephemeral path. Capturing it surfaced a genuine rendering bug in neat mode, logged as `open-problems.md` row 41 rather than silently worked around.

Light theme, per a colleague's defense-room feedback that the original dark theme was hard to read presenting live — a soft gray page (`F6F8FA`) with white cards, not stark white, after a second pass found pure white "too extreme." Same terminal-inspired identity throughout (Courier New headers, the same accent palette, now darkened for light-background contrast). Every speaker note was rewritten as the literal, word-for-word script: presenters read these aloud, they don't paraphrase from a cue, so every slide with a quote, a chart, a table, or a set of bullets opens its note by telling the audience what to look at before explaining it, in plain language throughout.

## Media

`media/what-it-looks-like.gif`, `media/safety-gate.png`, and `media/algorithm-trace.png` are real captures, not mockups or illustrations — produced by driving the actual prototype binaries through a real pty (Python's `pty` module) and rendering the captured terminal state (via `pyte`, a VT100 emulator) straight to PNG/GIF with Pillow and DejaVu Sans Mono. No X11, no screen recording, no sudo.

All three were recorded against **real, persistent, locally-browsable folders** on the presenting machine, not an ephemeral `/tmp` scratch path — specifically so that if a panelist asks "where is that," the answer is "right here," and it can be opened live:

- `~/Documents/SynapseOS-Demo/` — `report_draft.txt`, `budget.csv`, `Photos/{beach,sunset}.jpg` — used for slide 6's three-command sequence (list, rename, count), via `synapse tui scratch`.
- `~/Documents/SynapseOS-Demo-Logs/` — `app.log`, `debug.log`, `notes.txt` — used for slide 9's safety-gate capture (`delete all the log files in this folder`, declined after capturing the prompt; files are still there).
- `~/Documents/SynapseOS-Demo-Algorithm/` — `alpha.tmp`, `beta.tmp`, `notes.txt`, plus a built copy of `prototype/cmd/effexplain` — used for slide 7's algorithm-trace capture. `effexplain` builds its own synthetic fixture from the command text rather than reading the real directory (that's why the output shows a `/tmp/effexplain-.../` path, not this folder directly) — it's the algorithm's own debugging tool, not a general-purpose command, so this is expected and was left as-is rather than edited for a cleaner-looking path.

Two capture scripts (`capture_demo.py` for the interactive TUI, `capture_effexplain.py` for simple one-shot CLI output) lived in the session scratchpad, not this repo — one-off presentation tooling, not product code. If the demo needs re-capturing later:

- **TUI slides (6, 9):** open a real pty, run `synapse tui scratch` in it with `cwd` set to the real demo folder, script input with small per-keystroke delays (an instant full-string write raced the TUI's own input handling — see row 41 below), capture `pyte.Screen` snapshots at the moments worth showing, render each with Pillow. The machine this was captured on runs close to its RAM limit under load — Ollama inference occasionally took 40-50+ seconds per response instead of the usual ~10-30s, and one run hit an outright `context deadline exceeded` timeout. Budget generous waits (40-50s). Also: "how many photos are in here?" ran unusually long where "count the files in the Photos folder" answered quickly — more direct, explicit wording seems to matter for latency at this model size, not just correctness.
- **Algorithm slide (7):** no pty scripting needed — `effexplain` is a one-shot CLI with no interaction and no LLM call, so it's just run-and-capture, seconds not minutes.

**Found while capturing:** neat mode duplicates the echoed `> <task>` line on multi-step tasks (command + composed answer) — not on single-step conversational ones, and not in plain CLI mode or non-neat TUI mode. Reproduced live. Logged as `open-problems.md` row 41 with what's already been ruled out; root cause not yet found. The shipped images are clean — a cosmetic-only dedup in the capture script's renderer (not in product code) drops an immediately-repeated identical line before drawing, so the real bug is visible in the TUI today but not in these slides.

## Notes

Notes are the literal spoken script, not cues to paraphrase — presenters read them essentially verbatim per slide. That means every slide whose content is a quote, a chart, a table, or a set of bullets opens its note with a bridging sentence ("On screen is...", "Here's the core problem we're solving — please read the statement on screen.", "This chart shows...") before explaining anything, since nobody will invent that bridge live mid-presentation. Language is plain and concrete throughout, written for a listener with zero knowledge of this codebase — jargon is only used where the slide itself can't avoid it (RQ wording, baseline names), and even then the note explains it in the same breath. Round-7 figures on slides 11-12 are current as of this build (`prototype/pilot/results_round7.txt`); re-pull them if the analyser or corpus changes before the defense date.

## Rebuilding the deck

```sh
cd "thesis 1/defense"
npm install pptxgenjs react-icons react react-dom sharp   # once; node_modules is not committed
NODE_PATH="$(pwd)/node_modules" node build-deck.js
```

Edit content, numbers, sizing, or theme colors directly in `build-deck.js`, then rerun. See that file's own header comment for the `applyTheme` dependency on the Claude Code `pptx` skill, and its sizing/notes policy comment before changing either — in particular, note that `THEME.colors.dk1`/`lt1` are OOXML theme-slot names fixed by the schema, not literal shade descriptions; `dk1` currently holds the light gray page background and `lt1` the dark text color, `dk2` the white card background. Image paths in `addImage()` calls are resolved relative to the working directory the script is run from — run it from `thesis 1/defense/` as shown above, not from the repo root.
