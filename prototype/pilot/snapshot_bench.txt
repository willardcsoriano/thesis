Reading it: a snapshot taken before every command pays the cost of walking and stat'ing
the whole tree, whether nothing changed or one file did, because deciding what to
hardlink still means visiting every entry. The capture plan's cost is set by what the
command touches, not by how large the directory around it is. This is the trade the
capture plan is built to avoid, on a filesystem (ext4) with no cheaper primitive to
lean on; a copy-on-write filesystem such as btrfs would make the snapshot itself
closer to free and change which mechanism is worth building.
