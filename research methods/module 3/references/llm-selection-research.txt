  Compiled: 2026-06-30
===============================================================================

CONTEXT
-------
SynapseOS requires a locally-hosted multimodal LLM for two roles:
  1. Intent parsing — converting natural language user input into structured
     system actions (including bash/shell commands)
  2. Tier 3 vision fallback — grounding natural language intent onto a
     screenshot via visual understanding + mouse/keyboard simulation

Design constraint: smallest model that achieves acceptable accuracy for
offline, privacy-preserving, on-device operation on Debian 13 (Trixie).

This file documents the empirical basis for the model selection decision.

KEY FINDINGS FROM [A] — WESTENFELDER ET AL. 2025
===============================================================================

Models evaluated:
  - Llama 3.2 family: 1B, 3B, 8B
  - Qwen2.5-Coder family: 0.5B, 3B, 7B
  - GPT variants: 3.5-turbo through GPT-4 (hosted, for comparison)

Benchmark issues identified:
  - Over half of the InterCode NL2Bash dataset is erroneous
  - Authors created larger, manually verified datasets
  - Improved evaluation method: command execution + LLM assessment
    (95% confidence in functional equivalence — vs. prior syntax-only comparison)

Performance results (NL2Bash accuracy):

  Model                   | Baseline | Parsing/prompting | Fine-tuning (LoRA)
  ------------------------|----------|-------------------|-------------------
  Llama 3.2 - 1B         |   12%    |      ~33%         |       37%
  Llama 3.2 - 3B         |   17%    |       49%         |      ~49%
  Qwen2.5-Coder - 3B     |   26%    |       58%         |    (best small)
  Qwen2.5-Coder - 0.5B   |  lower   |      lower        |    untested
  GPT-4 (reference)      |  higher  |      higher       |        —

Key findings:
  - Parsing and in-context learning provided 21% and 19% average accuracy
    increases respectively for smaller models
  - Diminishing returns from these techniques on larger models
  - LoRA fine-tuning brought small models up to "baseline performance of
    larger unpruned variants"
  - Qwen2.5-Coder-3B is the strongest sub-7B performer out of the box

===============================================================================
CANDIDATE MODELS FOR SYNAPSEOS
===============================================================================

PRIMARY CANDIDATE
-----------------
Model:      Qwen2.5-Coder-3B (instruction-tuned)
Parameters: 3B
Strategy:   LoRA fine-tuning on NL2Bash + InterCode dataset
Accuracy:   58% with prompting alone; higher with fine-tuning
Size (Q4):  ~1.8GB quantized (fits on any modern machine, no dedicated GPU req.)
Why:
  - Code-specialized architecture — already biased toward shell/command syntax
  - Best sub-7B performer on NL2Bash benchmarks [A]
  - LoRA fine-tuning is lightweight and feasible without high-end GPU
  - Qwen2.5-Coder family explicitly evaluated on bash tasks in [A]
  - Offline-capable: runs via Ollama / llama.cpp on Debian 13

FALLBACK (if 3B too large for target hardware)
-----------------------------------------------
Model:      Llama 3.2-1B (instruction-tuned, LoRA fine-tuned)
Parameters: 1B
Accuracy:   37% after fine-tuning
Size (Q4):  ~650MB quantized
Caveat:     Borderline acceptable for simple commands; unreliable for complex
            cross-application workflows. Not recommended as primary.

ULTRA-SMALL OPTION (for future/constrained environments)
---------------------------------------------------------
Model:      T5-nl2bash (Flan-T5-base fine-tuned on NL2Bash corpus)
Parameters: ~250M
Accuracy:   Limited to NL2Bash corpus task types only
Source:     https://model.aibase.com/models/details/1915693260217147394
Caveat:     Extremely limited generalization. Not multimodal. Insufficient
            for Tier 3 vision fallback role. Shell-only, narrow task coverage.

NOT RECOMMENDED
---------------
- Hosted frontier models (GPT-4, Claude, etc.) — violates offline constraint
- Gemma-3-1B — poor NL2Bash performance per [B]
- General-purpose models without code specialization at sub-3B sizes


===============================================================================
FINE-TUNING PLAN (if adopted)
===============================================================================

Base model:    Qwen2.5-Coder-3B-Instruct
Method:        LoRA (Low-Rank Adaptation) — lightweight, no full retraining
Dataset:       NL2Bash corpus (9,305 pairs) + verified InterCode NL2Bash subset
               + custom SynapseOS task suite (shell operations category)
Hardware req:  ~8GB RAM sufficient with 4-bit quantization (Q4_K_M)
               No dedicated GPU required — CPU inference feasible on Debian 13
Tooling:       Ollama (serving) + Unsloth or PEFT (fine-tuning)
Eval metric:   Functional equivalence (execution-based, per [A] methodology)

Expected outcome (based on [A] findings):
  - LoRA fine-tuning on 1B model: +25pp over baseline
  - Equivalent or better gains expected for 3B model
  - Post-fine-tuning 3B should approach 7B baseline performance

REAUDIT — 2026-07-05
===============================================================================

Web research (WebSearch/WebFetch) to check whether a small (<4B) model
released since this file was compiled (2026-06-30) beats Qwen2.5-Coder-3B-
Instruct on NL2Bash/shell-generation specifically. Verdict: no. Candidates
checked:

  Qwen3-Coder-Next (Feb 2026)
    Strong benchmarks (SWE-Bench Verified >70%), but MoE with 80B TOTAL
    parameters (3B active per token) — all experts must stay resident in
    memory for CPU inference, blowing the ~2GB/8GB CPU-only budget by an
    order of magnitude. Rejected on hardware, not benchmark quality.

  Phi-4-mini (3.8B)
    Right size class (~2.2GB Q4_K_M, MIT license), but no NL2Bash/shell-
    specific benchmark evidence — only general reasoning scores (MMLU,
    GSM8K), which the execution-based NL2Bash methodology in [A] does not
    treat as equivalent evidence.

  SmolLM3-3B
    Most permissive license; beats base Qwen2.5-3B and Llama-3.2-3B — but
    not the code-specialized Coder variant this project actually uses.
    Not evidence against Qwen2.5-Coder-3B.

  LiteCoder-Terminal benchmark (arXiv 2605.29559, 2026)
    A genuine terminal-agent benchmark, but tests nothing under 4B
    (smallest is Qwen3-4B-Instruct, scoring 1-14% pass@1 pre-fine-tune on
    Terminal-Bench variants). Reinforces this project's existing premise
    that LoRA fine-tuning is necessary at this size class, rather than
    pointing at a better base model.

Conclusion: Qwen2.5-Coder-3B-Instruct selection stands. See decisions.md
D3 "Reaudited 2026-07-05" for the citable version of this finding.
